# pdfedit_v4

**WINTECH 문서편집기** (옛 이름: PDF 편집기). 브라우저에서 PDF를 열어 **본문 텍스트를 직접 수정**하고, 여러 PDF의 페이지를
합치고·순서 바꾸고·회전·삭제·삽입·추출하며, 한글 문서(HWP·HWPX)를 열어 고치고, 두 문서를 비교하고, 개인정보를 찾아 가립니다.
설치된 프로그램·바로가기·Program Files 폴더 이름은 0.079부터 **WINTECH DocEditor**입니다(그 전에는 `WINTECH_PDF`). 설치
프로그램이 Windows의 같은 업그레이드 코드를 써서, 업데이트하면 옛 WINTECH_PDF를 지우고 그 자리에 설치됩니다. 데이터 폴더
(`%USERPROFILE%\WINTECH_PDF`)와 설치 파일 이름(`WINTECH_PDF_Setup_<버전>.exe`, 자동 업데이트가 이 이름으로 찾음)은 그대로입니다.
하나의 Spring Boot 앱(jar 하나, 포트 하나)이 UI와 API를 모두 제공합니다.

**v4 = v3(0.035)에 글자 모양 편집·이동·텍스트 추가·그림 넣기·부분 서식을 더한 별도 프로그램입니다.** 현재 버전은 화면 맨 위에
표시됩니다. 새 기능은
[텍스트 편집 도구](#텍스트-편집-도구)에 있습니다.

이전에는 두 프로그램이었습니다 — v1(`pdf_edit_v1`: PDF 내용 편집기, Spring Boot 3 + PDFBox 2 + Thymeleaf)과
v2(페이지 편집기). 이 저장소는 둘을 합친 것입니다.

## 구조

- `backend/` — Spring Boot 4.1.2 + Apache PDFBox 3.0.8 (Java 25 toolchain, Gradle wrapper 포함)
  - `com.pdfedit.text` — 텍스트 런 추출(`TextExtraction`), 덮개 영역 계산(`VerticalBounds`), 글꼴 매칭(`FontMatcher`), 설치된 글꼴 색인(`SystemFonts`)
  - `com.pdfedit.text.RunPainter` — 수정한 줄을 원본 글리프 그대로 다시 그림(부분 서식의 굵게·색·크기·밑줄 포함)
  - `com.pdfedit.ocr` — 스캔한 쪽의 글자 인식: PaddleOCR PP-OCRv5 모델(`src/main/resources/ocr`, 한국어)을 ONNX Runtime
    1.31로 Java에서 직접 돌림(`OcrEngine`, Python 불필요), 쪽 단위 인식(`PageOcr`), 내보낼 때 보이지 않는 글자층(`OcrTextLayer`)
  - `com.pdfedit.service.TextEditService` — 텍스트 수정 기록·미리보기·PDF에 굽기
  - `com.pdfedit.service.ImageDrawing` / `controller.ImageController` — 페이지에 넣는 그림(올리기·검사·PDF에 그리기)
  - `com.pdfedit.service.PdfExportService` — 페이지 조립(순서·회전) + 페이지별 텍스트 수정 반영
- `frontend/` — React + TypeScript + Vite (`TextEditor` 컴포넌트가 텍스트 편집 화면)
- `e2e/` — 실제 화면을 브라우저로 조작하는 자동 테스트 ([테스트](#테스트))

## 실행

### 개발 (핫 리로드)

```
.\dev.ps1
```

백엔드(`:19000`)와 Vite 개발 서버(`:5173`)를 각각 새 창으로 띄웁니다. 브라우저에서는 `http://localhost:5173`을 여세요
(`/api`는 백엔드로 프록시됩니다). 백엔드는 개발 중 브라우저가 자동으로 열리지 않게 `PDFEDIT_NO_BROWSER=true`로 실행됩니다.

### 단일 jar

```
cd backend
.\gradlew.bat bootJar
java -jar build\libs\pdfedit-v2-backend-0.1.0.jar
```

`bootJar`가 `npm ci` + `npm run build`를 실행해 프런트엔드를 jar에 포함시킵니다 (Node 필요). 실행하면 비어 있는 포트(19000부터
탐색)를 골라 기본 브라우저를 엽니다. 이미 빌드된 `frontend/dist`를 쓰려면 `-PprebuiltFrontend`.

### Windows 설치 파일 (Setup.exe)

```
.\installer\build-installer.ps1
```

`installer\dist\WINTECH_PDF_Setup_<버전>.exe`가 만들어집니다 (JDK 25 + [WiX Toolset](https://wixtoolset.org) 필요). 설치 파일 안에
Java 런타임이 들어 있어 사용자 PC에 Java가 없어도 됩니다. 설치하면 시작 메뉴·바탕화면 바로가기가 생기고, 실행하면 브라우저가 열리며
작업 표시줄 트레이 아이콘(열기/종료)이 뜹니다. 이미 실행 중이면 바로가기를 다시 눌러도 새로 띄우지 않고 실행 중인 화면을 엽니다.
로그는 `%USERPROFILE%\WINTECH_PDF\app.log`. 아이콘은 `installer\WINTECH_PDF.ico`(기존 WINTECH_PDF와 동일).

- **배포는 Setup.exe로만 합니다** (포터블 폴더/zip은 만들지 않음). 개발 중 설치 없이 확인하려면 `-AppImageOnly` —
  `installer\build\app-image\WINTECH DocEditor\WINTECH DocEditor.exe`를 바로 실행할 수 있습니다.
- **업그레이드 코드** `{86BDF49F-B988-375C-BC21-F945E6338154}`는 바꾸면 안 됩니다(`build-installer.ps1`의 `$upgradeCode`). 이
  코드가 같아야 새 설치 파일이 이전 설치를 같은 프로그램으로 알아보고 교체합니다.
- 설치된 앱의 작업 보관 폴더는 `%USERPROFILE%\WINTECH_PDF\data`, 로그는 `%USERPROFILE%\WINTECH_PDF\app.log` 입니다. 앱을 지우거나 새
  버전으로 덮어 설치해도 이 폴더는 그대로 남습니다.
- **버전**: 화면·파일 이름·트레이에는 `app.version`(예: 0.035)이 쓰이지만, Windows 설치 파일 버전은 숫자 3자리여야 하고 낮은 버전으로는
  덮어 설치할 수 없으므로 `1.0.<버전×1000>`(0.035 → 1.0.35, 0.036 → 1.0.36)으로 넣습니다. 이전 v1 설치본(1.0.1) 위에 그대로
  업그레이드 설치됩니다.
- 코드 서명이 없어서 처음 실행할 때 Windows SmartScreen이 "알 수 없는 게시자" 경고를 띄울 수 있습니다 (더 알아보기 → 실행).

## 기능

- **텍스트 수정** — 페이지 카드의 `T` 버튼 → 본문 줄을 클릭해 직접 수정, 자동 저장, 페이지 단위 되돌리기
- 여러 PDF 업로드 후 페이지 단위로 합치기
- **자동 업데이트** — 설치한 앱(Setup.exe)은 시작할 때 GitHub의 최신 릴리스를 확인하고(결과는 몇 시간 동안 기억), 새 버전이 있으면 위에
  안내를 띄웁니다. `지금 업데이트`를 누르면 설치 파일을 내려받아 릴리스에 적힌 SHA-256과 맞는지 확인한 뒤 설치 프로그램을 열고 앱을
  종료합니다(Windows 권한 확인 창이 한 번 뜹니다). 맞지 않으면 설치하지 않습니다. `나중에`는 그 버전을 다시 알리지 않고, 첫 화면의
  `업데이트 확인`으로 언제든 다시 확인할 수 있습니다. 개발 실행에서는 꺼져 있습니다(`app.update.enabled`, 저장소는
  `app.update.repo`). 코드 서명이 없으므로 설치 프로그램 실행 시 SmartScreen 경고가 뜰 수 있습니다.
  - **새 버전 배포:** `app.version`을 올리고 커밋·푸시한 뒤 `.\installer\build-installer.ps1`로 빌드하고
    `.\installer\publish-release.ps1`을 실행하면 태그 `v<버전>`으로 릴리스를 만들어 설치 파일과 `.sha256`을 올립니다.
- PDF는 화면 어디에 끌어다 놓아도 열립니다(여러 개 가능). PDF가 아니거나 손상된 파일은 이유를 알려 주고, 나머지 파일은
  계속 엽니다.
- **암호가 걸린 PDF**는 열 때 암호를 묻습니다(틀리면 다시 묻고, "열지 않기"를 누르면 그 파일만 건너뜀). 맞는 암호로 연 문서는
  암호를 푼 사본으로 보관·편집합니다. 열기 암호 없이 편집·인쇄만 막아 둔 PDF는 묻지 않고 바로 열립니다. 암호는 업로드할 때 한 번만
  쓰고 저장하지 않습니다.
  - **원래 암호 다시 걸기** — 암호를 풀어서 연 문서의 페이지를 내보내거나 추출하면 "내보내는 PDF에도 암호를 걸까요?"를 묻습니다. 암호를
    두 번 넣으면 AES-256으로 잠그고, 원래 문서의 인쇄·복사 같은 제한(권한)도 그대로 다시 겁니다(여러 문서를 합치면 모두가 허용한 것만
    허용). 권한을 바꾸는 소유자 암호는 무작위로 만들고 버리므로, 새 암호로 열어도 제한은 풀리지 않습니다. `암호 없이 내보내기`도 고를 수
    있고, 내보내기 메뉴의 `암호 걸어 내보내기`로는 어떤 문서든 암호를 걸어 내려받습니다.
- 드래그로 페이지 순서 변경, 회전 · 삭제, 빈 페이지 삽입
- **페이지 복제** — 카드의 복제 버튼, 또는 선택한 페이지에서 `복제`(Ctrl+D). 고친 글자·추가한 상자·그림·가림 영역까지 그대로 바로 뒤에
  복사되며, 그 뒤로는 원본과 따로 고쳐집니다.
- **글자 인식(OCR)** — 스캔한 PDF(그림뿐인 쪽)의 글자를 읽어, 내보낸 PDF에서 검색·선택·복사할 수 있게 합니다(화면 모양은 스캔 그대로,
  글자는 보이지 않는 층으로 들어감). 글자가 없는 PDF를 열면 "스캔한 문서로 보입니다"와 `글자 인식` 버튼이 뜨고, `검토·보안 → 글자
  인식(OCR)`은 선택한 쪽(없으면 모든 쪽)을 차례로 인식합니다(쪽당 약 2초, 진행 표시와 `중지`). 인식한 쪽 카드에는 `OCR` 표시가 붙습니다.
  PDF 편집 화면에서는 `편집 → 글자 인식(OCR)`으로 보고 있는 쪽만 인식하고, 찾은 줄을 페이지 위에 초록 점선으로 보여 줍니다(`인식 표시`로 켜고 끔).
  점선 줄을 클릭해 고른 뒤 Ctrl+C(또는 `글자 복사`, 고른 줄이 없으면 그 쪽 전체)로 복사하고, 두 번 클릭·Enter·`고쳐 쓰기`로
  고칠 수 있는 텍스트 상자로 바꿉니다: 글자 크기·색은 스캔에 맞추고 스캔의 글자는 주변 바탕색으로 덮습니다(상자를 옮겨도 덮개는 제자리,
  상자를 지우면 스캔 글자가 다시 보임, Ctrl+Z로 되돌림). 고쳐 쓴 줄은 내보낼 때 보이지 않는 글자 층과 찾기에서 빠지고 상자의 글자가 대신합니다.
  - 모두 이 PC 안에서 처리하며 인터넷이 필요 없습니다. 모델은 PaddleOCR PP-OCRv5(한국어)이고 정확도는 300dpi 스캔에서 글자 100자당
    1~2자 정도 틀리는 수준입니다(시험: 공문서 형식, 주민번호·전화번호는 모두 정확). 200dpi보다 낮은 스캔은 오류가 늘어납니다.
  - 원래 글자가 들어 있는 자리는 다시 인식하지 않고, 가림 영역에 걸친 줄은 내보낼 때 넣지 않습니다. `이미지로 변환`으로 내보내면
    글자층도 없어집니다. 띄어쓰기는 모델이 낸 것을 쓰고, 없으면 글자 간격으로 넣습니다(빠뜨릴 수는 있어도 낱말 안에는 넣지 않음).
  - 인식한 글자는 앱 안에서도 쓰입니다. **개인정보 찾아 가리기**가 스캔한 주민번호·전화번호 등을 찾아(모델이 글자마다 본 위치로 번호
    부분만) 가리고, 내보낼 때 그 쪽을 그림으로 다시 만들어 번호를 실제로 지웁니다. **찾아 바꾸기**는 인식한 줄을 `스캔` 표시와 함께
    찾아 주며(그림이라 바꾸지는 않음), **문서 비교**는 스캔본끼리도 바뀐 어절을 표시합니다.
- 단일/다중 선택 후 일괄 회전·삭제·추출
- 선택한 페이지(또는 전체)를 새 PDF로 내보내기 — 텍스트 수정은 해당 페이지와 함께 따라갑니다

## 텍스트 편집 도구

편집 화면(페이지 카드의 `T` 버튼) 위쪽 막대와 상자 손잡이로 다음을 할 수 있습니다.

- **글꼴 표시·변경** — 줄을 클릭하면 `원본 글꼴 → 표시 글꼴 · 크기`가 보이고, 글꼴 목록(이 PC에 설치된 글꼴, 한글 글꼴 먼저)에서
  다른 글꼴을 고를 수 있습니다. 한컴 PDF처럼 글꼴 이름이 `T1`·`T2`인 Type3 글꼴은 "Type3 글꼴"로 표시됩니다.
  고른 글꼴에 입력한 글자가 없으면(예: 기호 글꼴에 한글) 저장할 때 "…에는 '한' 글자가 없습니다"라고 알려 주고 적용하지 않습니다.
- **글자 크기·굵게·색** — 줄 단위로 바꿉니다. 굵은 글꼴이 없는 글꼴은 획을 조금 두껍게 그려 굵게를 흉내 냅니다. 원본과 같은 값으로 되돌리면
  "바꾸지 않은 것"으로 처리되어 줄이 다시 원본 글리프 그대로 그려집니다. (모양을 바꾼 줄은 글리프 단위 재현 대신 고른 글꼴로 줄 전체를
  새로 그립니다.)
- **부분 서식** — 글자 수정 중에 일부 글자만 마우스나 Shift+방향키로 고른 뒤 `굵게`(Ctrl+B)·`밑줄`(Ctrl+U)·`색`·`크기`를 바꾸면 고른
  글자에만 적용됩니다(고르면 위쪽 막대가 그 글자의 모양을 보여 줍니다). 고르지 않고 굵게·색·크기를 바꾸면 줄 전체에 적용되고 그 항목의
  부분 서식은 사라지며, 밑줄은 줄 전체에 깔립니다. 이미 굵은 글자를 고르고 `굵게`를 누르면 굵기가 풀립니다. 줄 글자를 고치면 부분 서식은
  원래 글자를 따라가고(안에서 입력한 글자는 그 서식을 이어받음), 찾아 바꾸기에서도 유지됩니다. 추가한 텍스트 상자에서도 똑같이 글자를 골라 굵게·밑줄·색·크기를
줄 수 있고(상자 안의 글자를 고치면 서식이 글자를 따라감), 서식 있는 줄을 복사·복제해 만든 상자도 같은 부분 서식을 가집니다. 상자는
내보낼 때 줄마다 조각별로 굵기·색·크기·밑줄을 그립니다(상자의 글꼴은 설치된 글꼴이라 원본 글리프는 아님). 서식을 준 글자도 **페이지의 원본 글리프 그대로**
  굵기(획 겹쳐 그리기)·색·크기·밑줄만 바꿔 그리고, 서식 없는 글자는 원본과 같습니다. 줄 전체의 글꼴·크기·굵기·색을 바꾼 줄만 고른 글꼴로
  줄 전체를 새로 그립니다. 한 줄에 200군데까지입니다. (원본 글꼴 자체가 굵은 글꼴이면 굵기를 풀 수 없습니다.)
- **그림 넣기** — 위쪽의 `＋ 그림 추가`로 도장·서명·로고 같은 PNG·JPG·GIF·BMP 파일(10MB, 4천만 화소까지 — 화소 수는 그림을 풀기 전에 파일 머리에서 확인하므로 작은 파일에 거대한 그림을 숨긴
  "압축 폭탄"도 메모리를 채우기 전에 거절)을 페이지 가운데에 넣습니다. 끌어서 옮기고,
  모서리를 끌거나 위쪽 막대의 `너비`로 크기를 바꾸며(비율 유지), `복제`·`삭제`·실행 취소가 됩니다. `Ctrl+C`·`Ctrl+V`로 다른 페이지에도 복사해
붙일 수 있고(같은 문서면 같은 그림을 그대로, 다른 문서면 그림을 옮겨 올립니다), 서명을 여러 페이지에 넣을 때 씁니다. `흰 배경 투명`을 켜면 사진으로 찍은
  서명의 흰 종이가 투명해집니다. 화면 캡처나 복사한 그림은 `Ctrl+V`로 바로 붙여넣을 수 있습니다. 휴대폰으로 찍은 JPG의 회전 정보(EXIF)는
올릴 때 읽어서 사진을 바로 세워 저장합니다. 같은 그림은 한 번만 올려 여러 번 쓸 수 있고, 미리보기·내보내기·재시작 뒤에도 그대로이며 문서를 지울 때 함께
  지워집니다. 한 문서에 그림 50개, 한 페이지에 100곳까지. 회전된 페이지에는 넣을 수 없습니다.
- **이동** — 줄 왼쪽의 ✥ 손잡이를 끌거나 Alt+방향키(1pt, Shift는 10pt)로 옮깁니다. 원래 자리는 배경색으로 덮고, 새 자리에 줄을 다시 그립니다.
  글자를 고치지 않고 옮기기만 하면 원본 글리프 그대로 옮깁니다. `원위치` 버튼은 그 줄의 수정·모양·이동을 모두 되돌립니다.
- **텍스트 추가** — 위쪽의 `＋ 텍스트 추가`를 누르고 페이지의 원하는 곳을 클릭해 입력합니다(Enter는 줄바꿈). 글꼴·크기·굵게·색을 고를 수 있고
  (글자를 일부만 골라 서식을 줄 수도 있습니다 — [부분 서식](#텍스트-편집-도구)) ✥로 옮기거나 `삭제`할 수 있습니다. 기존 글자를 지우지 않으므로 덮개 없이 그 위에 그려지며, 빈 페이지와 글자 정보가 없는 스캔 페이지에도
  쓸 수 있습니다. 한 페이지에 200개까지.
- 변경은 자동 저장되고 미리보기·썸네일·내보내기에 모두 반영됩니다. 새 미리보기가 도착하기 전까지는 상자가 글자를 대신 보여 줍니다.
- **삭제** — 추가한 텍스트 상자는 상자 오른쪽의 ✕, 위쪽 막대의 `삭제`, 또는 선택한 상태에서 `Delete` 키로 지웁니다.
- **실행 취소/다시 실행** — 위쪽 `↶`/`↷` 버튼 또는 Ctrl+Z / Ctrl+Y. 줄 수정·모양 변경·이동·텍스트 추가/삭제·페이지 되돌리기를 한 단계씩
  되돌리고(연속 방향키 이동이나 크기 입력은 한 단계로 묶음), 되돌린 결과도 서버에 다시 저장됩니다. 페이지마다 따로 기록하며(최대 100단계)
  편집 화면을 닫거나 다른 페이지로 넘어가면 비워집니다.
- 글이 길어져 같은 줄의 오른쪽 글자나 페이지 끝을 넘을 것 같으면 줄 아래에 "글이 길어져 겹칠 수 있음" 경고가 뜹니다 (브라우저 글꼴로
  잰 추정치입니다). 세로 쓰기와 문단 재배치(줄바꿈 자동 맞춤)는 아직 없습니다.
- **PC에 없는 글꼴** — 페이지가 쓰는 글꼴이 이 PC에 설치되어 있지 않으면 편집 화면 위에 "이 PC에 없습니다" 안내와 `받는 방법`이 뜹니다
  (줄을 선택하면 위쪽 막대에도 표시). 나눔·Noto·Pretendard는 받는 곳 링크를, 그 밖의 글꼴은 웹 검색 링크와 출처 안내를 보여 줍니다. 글꼴에는
  저작권이 있어서 앱이 대신 내려받거나 설치하지는 않습니다. 글꼴을 설치한 뒤 `글꼴 다시 읽기`(편집 화면의 ⟳ 버튼, 첫 화면 위쪽, 안내
  창)를 누르면 앱을 다시 켜지 않고도 새 글꼴을 읽고, 페이지가 쓰는 글꼴이 설치되어 있으면 새로 입력한 글자도 그 글꼴 그대로 그려집니다.
  읽는 글꼴은 TrueType(.ttf, .ttc)입니다. **.otf(CFF 글자 모양)는 PDFBox 3.0.8이 PDF에 심지 못해서 쓰지 못합니다**(내부가 TrueType 방식인
  드문 .otf는 읽힙니다). 앱은 이런 글꼴을 이름으로 찾아 두었다가 알려 줍니다: 첫 화면 위쪽에 "⚠ .otf 글꼴 N개는 읽지 못함", 페이지가
  쓰는 글꼴이 그것이면 편집 화면 안내와 `받는 방법` 창에 "이 PC에는 .otf로만 설치되어 있으니 .ttf 버전을 설치하세요", `글꼴 다시 읽기`로
  새 글꼴이 안 잡힐 때도 같은 안내가 붙습니다. 받는 곳에 형식이 여러 가지면 TTF를 고르세요.
- **글꼴 섞임** — 원본 글꼴(서브셋)에 없는 글자를 새로 치면 그 글자만 대체 글꼴로 그려져 모양이 다를 수 있습니다. 위쪽 막대에 해당 글자와
  `줄 전체 글꼴 통일` 버튼이 나타나며, 누르면 그 줄을 한 가지 설치 글꼴로 다시 그립니다. 이름으로 종류를 알 수 없는 글꼴(예: `HYwulM`)은
  Type3처럼 글자 모양을 비교해 명조/고딕·굵기를 고릅니다.

### 단축키

| 키 | 동작 |
|---|---|
| Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) | 실행 취소 / 다시 실행 (글자를 입력한 직후의 상자 안에서는 브라우저의 글자 단위 취소가 먼저) |
| Ctrl+S / Ctrl+Shift+S | PDF로 내보내기(다운로드) / 수정 즉시 반영 (수정은 입력하는 대로 자동 반영되며, 파일로 받으려면 내보내기) |
| Esc | 추가 모드 취소 → 입력 중이면 상자에서 나가기 → 선택 해제 → 편집 화면 닫기 (차례대로) |
| T | 텍스트 추가 도구 켜기/끄기 (글자 입력 중이 아닐 때) |
| Delete (Backspace) | 선택한 추가 텍스트·그림 삭제 |
| 방향키 / Shift+방향키 | 선택한 줄·상자를 1pt / 10pt 이동 (글자 입력 중에는 Esc로 나온 뒤) |
| Alt+방향키 | 글자 입력 중에도 1pt 이동 (Alt+Shift는 10pt) |
| Ctrl+B / Ctrl+U | 굵게 / 밑줄 켜기·끄기 (글자를 고른 상태면 고른 글자만) |
| Ctrl+C / Ctrl+V | 선택한 줄·상자를 복사 / 붙여넣기 (같은 페이지는 12pt씩 어긋나게, 다른 페이지로 옮겨 붙이면 같은 자리에, 부분 서식도 함께). 입력 중 글자를 선택한 상태의 Ctrl+C는 글자 복사. 클립보드에 그림(캡처, 복사한 서명 등)이 있으면 Ctrl+V가 그림을 페이지에 붙여넣음 |
| Ctrl+D | 선택한 줄·상자를 바로 옆에 복제 |
| Enter / F2 | 선택한 상자에 글자 입력 시작 (더블클릭, 선택한 상자를 한 번 더 클릭해도 됨) |
| Ctrl+F / Ctrl+H | 찾아 바꾸기 |
| Ctrl+= / Ctrl+- / Ctrl+0 / Ctrl+9 / Ctrl+휠 | 확대 / 축소 / 폭에 맞춤 / 쪽 맞춤(쪽 전체가 보이게) / 확대·축소 |
| 페이지 목록: Ctrl+A, Ctrl+D, Delete, R / Shift+R, Esc | 전체 선택, 선택 페이지 복제, 선택 페이지 삭제, 오른쪽·왼쪽 회전, 선택 해제 |
| Ctrl+] / Ctrl+[ | 글자 크기 +1pt / −1pt |
| Ctrl+←/→ | 이전 / 다음 페이지 (PageUp/PageDown은 화면 스크롤에 써야 해서 쓰지 않음) |

한글 입력(조합) 중에는 단축키가 동작하지 않아 글자가 깨지지 않으며, 글자 키(Z·Y·S·B·T)는 한글 입력 상태에서도 자판 위치로 인식합니다.

## 작업 보관, 내보내기, 찾아 바꾸기

- **작업 보관** — 올린 문서와 수정 내용(고친 줄·글꼴·이동·부분 서식·추가한 텍스트와 그림)은 서버의 데이터 폴더(`PDFEDIT_DATA_DIR`, 기본
  `%USERPROFILE%\WINTECH_PDF\data`)에 저장되고, 브라우저도 페이지 목록을 기억합니다. 새로고침하거나 앱을 다시
  시작해도 "이전 작업을 불러왔습니다"로 이어서 작업하며(`모두 지우기`로 비움), 정한 기간(기본 30일, 첫 화면 위쪽의 `작업 보관 N일`을 눌러 7일~1년으로 바꿈 — 데이터 폴더의
  `settings.properties`에 저장, 처음 값은 `app.retention-days`·환경변수 `PDFEDIT_RETENTION_DAYS`) 동안 한 번도 열지 않은 문서만
  지워집니다. 저장이 서버에 닿지 않았을 때는 입력한 내용을 화면에 남기고 `다시 시도`를 보여 주며, 서버가 거절한 변경(글꼴에 없는 글자 등)은
  자동으로 취소합니다.
- **내보내기** — `PDF로 내보내기`(Ctrl+S)는 원본 파일 이름 기준 `이름_수정본.pdf`(여러 파일이면 `merged.pdf`)로 받습니다. `이미지로 변환`을
  켜면 모든 페이지를 그림으로 바꿔서 수정 전 글자가 파일에서 **완전히** 사라지지만(레닥션) 검색·복사는 할 수 없습니다. 켜지 않으면 수정한 줄의 원래
  글자가 덮개 아래 남아 있다는 경고가 편집 화면에 뜹니다.
- **개인정보 가리기(검증하는 레닥션)** — 목록 위의 `개인정보 가리기`에서 주민·외국인등록번호(생년월일 확인), 휴대전화·전화번호,
  이메일, 카드번호(검증 숫자 확인), 계좌번호(추정), 운전면허·여권번호, 사업자등록번호(기본 꺼짐)와 직접 입력한 글자를 모든 페이지에서
  찾습니다. 고른 항목은 **가림 영역**이 되어 썸네일에 검은 상자로 보입니다. `직접 그려서 가리기`(또는 결과의 `N쪽`)에서는 페이지 위를
  끌어 영역을 그리고, ✕나 Delete로 지웁니다. 원본은 바뀌지 않아 내보내기 전에는 언제든 고칠 수 있습니다.
  - **내보낼 때 실제로 지웁니다:** 영역 아래 글자를 PDF 내용에서 글자 단위로 잘라 내고(옆 글자는 제자리에 그대로, 검색·복사 가능),
    영역을 검은색으로 칠하고, 영역에 걸친 링크·주석을 뺍니다. 그다음 페이지를 **두 가지 방법으로 다시 읽어** 영역 안에 글자가 남지 않았는지
    확인합니다.
  - 영역 아래에 그림(스캔 이미지·사진)이 있거나, 세로쓰기·여러 번 그려지는 양식처럼 글자만 잘라 낼 수 없거나, 확인에서 글자가 발견되면 **그
    페이지만** 그림으로 바꾸고 영역을 픽셀에 칠합니다(그 페이지의 글자는 검색되지 않음). 내보낸 뒤 화면에 "가림 영역 N곳 적용 · 글자 M개
    삭제 확인 · 그림으로 바꾼 쪽"이 표시됩니다.
  - 글자를 그림(윤곽선)으로 그린 PDF는 글자로 찾을 수 없으니, 그런 곳은 직접 그려서 가리세요(검은 상자가 그 위를 덮습니다). 문서 정보
    (제목·작성자)나 책갈피에 적힌 내용은 가리지 않습니다.
- **한글 문서(HWP·HWPX) 보기·편집** — `.hwp`/`.hwpx` 파일을 끌어다 놓거나 `파일 열기`로 고르면 한글 편집 화면이 열립니다.
  오픈소스 [rhwp](https://github.com/edwardkim/rhwp)(MIT) v0.8.7의 편집기(rhwp-studio)를 **앱 안에 넣어** 쓰므로 인터넷이 없어도
  되고 문서가 PC 밖으로 나가지 않습니다(외부 웹 글꼴도 끔). 한글과 비슷한 메뉴·도구 상자로 글자·문단 모양, 표, 그림, 쪽 설정 등을
  고치고, 위쪽의 `HWPX로 저장`/`HWP로 저장`으로 내려받습니다(원래 형식이 파란 버튼). 저장하지 않은 수정이 있으면 닫을 때 묻습니다.
  인쇄(PDF로 저장 포함)는 편집 화면의 `파일` 메뉴에서 합니다. 한컴 전용 글꼴은 함께 들어 있는 오픈소스 글꼴(나눔·Noto·Pretendard
  등)로 비슷하게 표시되며, 한컴 글꼴이 PC에 있으면 그것을 씁니다. rhwp는 1.0 전 단계라 복잡한 문서는 한글 프로그램과 다르게 보일 수
  있습니다. 편집기는 `tools/build-hwp-studio.ps1`(버전 지정 가능)로 다시 만들어 `frontend/public/hwp-studio`에 넣으며, 라이선스는
  그 폴더의 `LICENSE-rhwp.txt`·`THIRD_PARTY_LICENSES.md`에 있습니다.
- **문서 비교** — 목록 위의 `문서 비교`에서 올린 두 PDF(이전 판·새 판)를 고르면 두 문서를 나란히 보여 주고, 지워진 글자는 이전 판에
  빨간색, 추가된 글자는 새 판에 초록색으로 표시합니다. 왼쪽 목록에 쪽별로 바뀐 글자(− / +)가 나오고, 누르거나 ⇤ ⇥로 바뀐 쪽 사이를
  오갑니다. 문서 전체를 이어서 비교(줄 → 어절 순, Myers diff)하므로 글자가 다음 쪽으로 밀리기만 한 것은 바뀐 것으로 치지 않습니다.
  `모양 차이`를 켜면 보고 있는 쪽을 그림으로 비교해 그림·선·도장 같은 글자 외 차이를 주황색 점선으로 표시합니다(쪽 크기가 다르면 생략).
  올린 원본끼리 비교하며 이 앱에서 고친 내용은 들어가지 않습니다(500쪽 이하).
- **찾아 바꾸기** — Ctrl+F로 모든 페이지의 글자를 찾고(대소문자 구분 선택), 결과를 눌러 그 페이지로 가거나 `모두 바꾸기`로 한꺼번에 바꿉니다.
  줄의 글꼴·크기·색·이동은 그대로 두고 글자만 바꾸며, 한 줄 안의 글자만 찾습니다. 바꾼 뒤에는 페이지별 `이 페이지 되돌리기`로 되돌립니다.
- **회전된 페이지** — 원본에 `/Rotate`가 지정된 페이지(스캔·휴대폰 PDF에 흔함)는 올릴 때 보이는 모양 그대로 회전 없는 페이지로 바꿔서 편집할 수
  있습니다. 이 페이지의 주석(링크·메모)은 위치가 맞지 않아 빠집니다.
- **접속 비밀번호** — 다른 사람이 접속할 수 있는 곳(NAS 등)에서는 환경변수 `PDFEDIT_PASSWORD`를 설정하면 브라우저가 비밀번호를 묻습니다
  (사용자 이름은 아무거나). 설정하지 않으면 로그인이 없습니다.
- **메뉴(리본)** — 한글·오피스처럼 아이콘 버튼을 묶음별로 보여 줍니다. 페이지 목록 위에는 파일(PDF 열기·빈 페이지·모두
  지우기) · 편집 · 선택한 페이지(회전·추출·삭제) · 검토·보안(개인정보 가리기·문서 비교) · 내보내기 묶음이 한 줄로 있습니다. PDF 편집
  화면은 한글 문서 편집 화면과 같은 모양입니다: 맨 위 줄(페이지 목록·문서 이름·이전/다음 쪽·저장 상태·인쇄·PDF로 내보내기), 메뉴 줄(파일·
  편집·보기·입력·서식·도구, 오른쪽 ⌃로 도구 상자 접기), 고른 메뉴의 도구 상자, 서식 줄(인쇄·실행 취소·다시 실행 | 글꼴·크기 |
  굵게·밑줄·글자 색), 맨 아래 상태 표시줄(쪽 이동·선택한 줄의 정보·확대 비율).
- **인쇄** — 페이지 목록의 `인쇄`, PDF 편집 화면의 🖨·`인쇄`, 또는 Ctrl+P. 내보낼 때와 똑같은 PDF(고친 내용·가림 영역·이미지로
  변환 설정 반영)를 만들어 브라우저의 인쇄 창을 엽니다. 페이지 목록에서 몇 쪽을 선택해 두면 그 쪽만 인쇄합니다. 브라우저가 바로
  인쇄하지 못하면 PDF를 새 탭으로 열어 주며, 거기서 인쇄하면 됩니다. 한글 문서는 한글 편집 화면의 `파일` 메뉴에서 인쇄합니다.
- **편집 화면** — 줄을 한 번 클릭하면 선택(이동·모양 변경), 한 번 더 클릭·더블클릭·Enter로 글자 입력입니다. 상자 본체나 ✥를 끌면 다른 줄의
  왼쪽 끝·기준선에 정렬선이 붙으며 옮겨집니다. 위쪽 막대에는 글꼴 검색 목록(최근 사용 포함), 바꾼 줄이 "원본 글꼴 유지"인지 "대체 글꼴로 다시
  그림"인지의 표시, 확대/축소가 있습니다.

## 텍스트 수정이 동작하는 방식과 한계

- 수정한 줄은 가능하면 **원래 글자를 페이지 내용에서 실제로 지운 뒤 새 글자를 그립니다.** 원래 글자를 그린 글자 표시 연산만 같은 길이의
  빈 이동으로 바꾸므로 뒤따르는 글자의 위치는 그대로이고, 덮는 사각형이 없어서 굵은 표선이나 칸 음영 근처에서도 모양이 변하지 않습니다.
  지운 뒤 페이지의 글자를 다시 읽어 **수정한 줄만 사라졌는지 확인**하고, 확인되지 않는 경우(같은 연산이 수정하지 않은 줄도 그리는 경우,
  두 번 그려지는 양식 개체, 세로쓰기, Type3 글꼴 안의 글자 등)에는 예전처럼 **배경색으로 덮은 뒤 다시 그립니다.** 덮은 경우에는 원본 글자가
  PDF 안에 남아 있으므로 레닥션(정보 삭제) 용도로는 `이미지로 변환`을 켜세요. 줄을 고르면 위쪽 막대에 `원본 글자 삭제됨` 또는
  `원본 글자 가려짐`이 표시됩니다.
- 원본 글꼴을 쓸 수 없어 설치된 글꼴로 줄 전체를 그릴 때는, 원본 문장의 폭에 맞춰 글자를 가로로 0.7~1.15배 범위에서 늘이거나 줄여
  원본이 차지하던 자리를 유지합니다. 글꼴을 직접 고른 줄에는 적용하지 않습니다.
- **바뀌지 않은 글자는 원본 그대로** 다시 그립니다. 글자마다 원본 PDF의 글꼴 객체와 글리프 코드, 크기, 장평, 자간, 글자색, 굵게(획 겹쳐
  그리기)를 기록해 두었다가 같은 값으로 그리므로, 글꼴이 서브셋으로만 들어 있어도 모양·굵기·색이 그대로입니다. 줄 안에서 글꼴이 섞여 있어도
  글자별로 유지됩니다.
- **새로 입력한 글자**는 바로 앞(또는 바꾼) 글자의 크기·색·굵기·자간을 따르고, 글꼴은 (1) 그 페이지가 같은 글꼴로 이미 쓰고 있는 글자면
  원본 글리프 그대로, (2) 글꼴이 전체 임베드되어 있으면 그 글꼴, (3) 그 외에는 **이 PC에 설치된 글꼴**(맑은 고딕·바탕·돋움·굴림,
  나눔고딕·나눔명조, 휴먼명조·휴먼고딕 등) 순으로 고릅니다. 앱에는 글꼴이 들어 있지 않습니다 → [글꼴](#글꼴) 참고.
- 회전(`/Rotate`)된 페이지는 올릴 때 회전 없는 페이지로 바뀌므로 편집할 수 있습니다. 다만 이 기능이 생기기 전에 올려 둔 문서는 그대로
  회전 상태라 편집이 막히니, 그 PDF를 다시 올리세요.
- **저장된 사본** — 올린 PDF는 서버(내 PC)의 데이터 폴더에 7일간 보관되고, 위쪽의 `모두 지우기`를 누르면 즉시 삭제됩니다.
- 줄 단위로 편집합니다 (PDFBox가 같은 줄의 글자를 한 덩어리로 돌려줌). 표처럼 칸이 많은 문서는 한 칸만 고쳐도 같은 줄 전체가 대상입니다.
- 한컴(HWP)이 만든 PDF처럼 글꼴이 **Type3**(글자 모양이 글꼴 파일이 아니라 그리기 프로그램, 이름은 `T1`·`T2`)인 경우도 글자별로
  재현합니다. 이런 글꼴은 이름으로 명조인지 고딕인지, 굵은지 알 수 없어서, 글꼴에 없는 새 글자는 그 글꼴의 글자 몇 개를 그려 보고
  설치된 글꼴(명조/고딕 × 보통/굵게) 중 모양이 가장 비슷한 것으로 그립니다.
- 글자별 재현이 안 되는 줄(글꼴이 Identity가 아닌 CMap을 쓰는 경우 등)은 줄 전체를 한 가지 대체 글꼴로 그립니다.
- 스캔 이미지 PDF처럼 글자 정보가 없는 페이지는 편집할 텍스트가 없습니다.
- 대체 글꼴은 실제로 쓴 글자만 서브셋으로 PDF에 넣으므로, 수정해도 파일이 거의 커지지 않습니다.

## 글꼴

글꼴은 앱에 포함하지 않고 **실행하는 PC에 설치된 TrueType 글꼴(.ttf/.ttc)** 을 씁니다. Windows(`%WINDIR%\Fonts`, 사용자 설치 폴더),
Linux(`/usr/share/fonts`, `~/.fonts` 등), macOS의 글꼴 폴더를 처음 필요할 때 한 번 훑어서 글꼴 파일 안의 이름으로 찾으므로, 나중에
설치한 글꼴은 `글꼴 다시 읽기`(⟳)를 누르면 앱을 다시 켜지 않고도 반영됩니다.

- 원본 글꼴과 같은 계열의 글꼴이 있으면 그것을, 없으면 비슷한 계열(명조 계열 → 나눔명조·바탕, 고딕 계열 → 맑은 고딕·나눔고딕·돋움·굴림)을
  씁니다. 휴먼명조·휴먼고딕은 한컴 오피스가 설치된 PC에서만 정확히 일치합니다.
- 한글을 그릴 수 있는 글꼴이 하나도 없으면 글자가 사라지지 않도록, 수정을 저장하는 시점에 "한글 글꼴을 찾지 못했습니다"라고 알립니다.
- Windows에는 맑은 고딕이 기본 설치되어 있어 따로 할 일이 없습니다.
- 글꼴 폴더를 더 지정하려면 환경변수 `PDFEDIT_FONT_DIRS`에 PATH처럼 구분해서 적습니다.
- 화면 맨 위에 앱 버전(`app.version`, 변경할 때마다 0.001씩 올림)과 읽어온 로컬 글꼴 개수가 표시됩니다.

## 테스트

세 겹으로 되어 있고, 위로 갈수록 실제 사용에 가깝습니다.

```
cd backend;  .\gradlew.bat test            # 백엔드: 글자 추출·지우기·그리기·API (페이지를 그려서 픽셀로 확인하는 테스트 포함)
cd frontend; npx vitest run                # 화면 부품: 상자·서식 계산·겹침 경고 등 (jsdom)
cd backend;  .\gradlew.bat bootJar         # 아래 화면 테스트가 쓸 jar를 먼저 만듭니다
cd e2e;      npm ci; npm test              # 실제 화면: 앱을 새로 띄워 Edge로 조작
```

- **화면 테스트(`e2e/`, Playwright)** 는 jar를 빈 데이터 폴더·별도 포트(19090, `E2E_PORT`로 변경)로 띄우고, 이 PC에 설치된 **Microsoft Edge**
  (`E2E_BROWSER=chrome`이면 Chrome)를 조작합니다. 브라우저를 따로 내려받지 않습니다. PDF·그림은 테스트가 직접 만들어 쓰므로 준비할 파일이
  없습니다. 지금은 줄 수정→내보내기한 PDF의 글자 확인, 실행 취소, 부분 서식(굵게·밑줄·크기·색), 그림 넣기·크기 조절·삭제, 암호 PDF 열기(틀린 암호·취소 포함)→암호 다시 걸어 내보내기(새 암호를 묻는지), 페이지 복제(고친 글자째로), 쪽 맞춤, 스캔 PDF 글자 인식→내보낸 PDF에서 글자 찾기, 개인정보 찾아 가리기→내보낸 파일에서 글자가 사라졌는지, 가림 영역 직접 그리기·지우기, 두 문서 비교(바뀐 어절 표시·모양 차이), 한글 문서 열기→글자 입력→HWPX·HWP 저장(입력한 글자가 저장 파일에 들어 있는지, 바깥
  서버로 나간 요청이 없는지)을 확인합니다.
  실패하면 `e2e/test-results`에 화면 캡처와 추적 파일(`npx playwright show-trace`)이 남습니다.
- 화면 글자 크기·모양 같은 "보기에 맞는가"는 자동으로 알 수 없어서, 그런 변경은 직접 화면으로 확인합니다.

## 참고

- 외부 도구(LibreOffice, Tesseract, qpdf)는 쓰지 않습니다. 글자 인식은 앱에 든 모델과 ONNX Runtime으로, 암호 걸기는 PDFBox만으로
  합니다. 문서 변환을 붙일 때는 별도 설치가 필요합니다.
- ONNX Runtime jar(약 49MB)에는 Windows·Linux·macOS용 실행 파일이 모두 들어 있습니다. 설치 파일은 `gradlew bootJarWindows`로 만든
  Windows용만 남긴 jar(`*-windows.jar`, 약 42MB 작음)를 쓰고, 화면 테스트는 보통 `bootJar`를 씁니다.
- 이전 `pdf_edit_v1`에서 가져온 것: 텍스트 추출·글꼴 매칭·덮개 영역·내보내기 로직(PDFBox 3으로 이식, 같은 입력에서 v1과 **픽셀
  단위로 동일한 결과**임을 확인), 편집 UI(Thymeleaf → React). 버린 것: v1이 v2를 자식 프로세스로 띄우던 구조와 홈 링크, 두 앱의 포트 분리.
