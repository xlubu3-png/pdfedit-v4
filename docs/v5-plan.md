# WINTECH 문서편집기 v5 계획

v4(0.118)를 바탕으로 이어서 크게 고친 다음 판입니다. **처음부터 새로 짜지 않습니다.** 지금의 기능과 테스트를 그대로 가져가면서
아래 네 가지 불편을 고칩니다. 단계마다 쓸 수 있는 상태로 릴리스하고, 각 단계는 측정·테스트로 확인한 뒤 다음으로 넘어갑니다.

| 불편 | 목표 | 단계 |
|---|---|---|
| 설치 문제 | 설치·업데이트가 실패하지 않고, 실패하면 이유를 알려 줌 | 1 |
| 느림 | 켜기·큰 문서 열기·썸네일이 눈에 띄게 빨라짐 | 0(측정), 2 |
| 프로그램 창으로 쓰고 싶음 | 브라우저 탭이 아니라 자기 창(작업 표시줄 아이콘)으로 실행 | 3 |
| 화면이 복잡함 | 자주 쓰는 일이 한두 번 클릭으로, 나머지는 정리해서 숨김 | 4 |

마지막으로 이름·버전을 v5로 정리합니다(5단계).

## 지켜야 할 것 (모든 단계 공통)

- 화면의 글자, 오류 메시지, 릴리스 노트는 모두 **한글**입니다.
- **자동 업데이트를 깨지 않습니다.** 설치된 v4가 v5를 업데이트로 받아야 합니다.
  - 설치 파일 이름 `WINTECH_PDF_Setup_<버전>.exe`와 `.sha256`(업데이트가 이 이름으로 찾음), 업그레이드 코드
    `{86BDF49F-B988-375C-BC21-F945E6338154}`, 데이터 폴더 `%USERPROFILE%\WINTECH_PDF`는 바꾸지 않습니다.
  - Windows 설치 버전은 `1.0.<app.version×1000>`이므로 새 버전 번호는 항상 이보다 커야 합니다(5단계 참고).
- 기능을 빼지 않습니다. 메뉴에서 옮기거나 숨기는 것은 되지만, 할 수 있던 일은 계속 할 수 있어야 합니다.
- 테스트(백엔드 JUnit, 화면 vitest, e2e Playwright)를 지키고, 고친 것마다 테스트를 더합니다. 테스트를 끄거나 건너뛰지 않습니다.
- 오픈소스를 더하면 라이선스를 확인합니다(GPL·AGPL은 넣지 않음, `licenses/README.md`). `THIRD-PARTY-NOTICES.txt`는 빌드가
  자동으로 만들고, 원문이 없는 라이브러리는 빌드가 멈추니 `backend/notices.gradle`에 더합니다.
- 회사 안에서만 쓰는 프로그램입니다. 문서는 PC 밖으로 나가지 않아야 합니다(외부 서버로 보내는 기능 금지).

## 0단계: 지금이 얼마나 느린지 재기 (먼저)

느린 곳을 추측으로 고치지 않습니다. 같은 PC에서 반복해 잴 수 있는 측정 스크립트를 만들고 결과를 이 문서에 표로 남깁니다.

- 잴 것: 앱 켜기(바로가기 → 첫 화면), 100쪽 PDF 열기(올리기 → 첫 썸네일, 모든 썸네일), 편집 화면 열기(미리보기 표시),
  PDF로 내보내기(100쪽, 이미지로 변환·용량 줄이기 켬/끔), 글자 인식 1쪽, 스캔 글자 고쳐 쓰기 1줄, 사진으로 내보내기 10쪽, 메모리 최대치.
- 방법: 백엔드 API를 직접 부르는 스크립트(시간)와 Playwright(화면 기준 시간). 테스트용 PDF는 스크립트가 만듭니다(실제 문서 금지).
- 결과로 2단계에서 무엇을 먼저 할지 정합니다.

## 1단계: 설치·업데이트 안정화

있었던 문제: 0.118 시험 설치에서 프로그램 본체 `app\WINTECH_PDF.jar`만 빠진 채로 설치되어, 실행해도 아무 안내 없이 꺼졌습니다
(로그에도 아무것도 남지 않음). 다시 설치하자 해결. 원인은 백신 격리 또는 실행 중인 이전 버전 위에 설치한 것으로 추정됩니다.

- **켜지지 못하면 알리기:** 시작할 때 본체·실행 환경이 온전한지 확인하고, 문제가 있으면 한글 안내 창(원인, 다시 설치하는 방법,
  로그 위치)을 띄웁니다. jpackage 실행 파일은 jar가 없으면 아무것도 못 하므로, 확인은 설치 후 첫 실행이나 별도의 작은 실행기에서
  해야 할 수 있습니다(3단계의 실행기와 함께 설계).
- **이미 켜진 이전 버전 넘겨받기:** 지금은 두 번째 실행이 켜져 있는 쪽으로 브라우저만 열고, 연결이 안 되면 1분 뒤 조용히
  끝납니다(`InstalledApp`). 켜진 쪽의 버전도 기록해, 버전이 다르면 이전 버전에게 종료를 요청하고(로컬 전용 API) 넘겨받습니다.
  넘겨받지 못하면 안내 창을 띄웁니다.
- **설치 전에 이전 버전 끄기:** 직접 설치 파일을 실행해도 켜진 앱이 확실히 꺼지게 합니다(설치 프로그램 설정 또는 실행기에서).
- **업데이트 확인:** `지금 업데이트` 뒤 새 버전이 실제로 켜졌는지 확인하고, 실패하면 이전 설치 파일 받는 곳을 안내합니다.
- **코드 서명(회사 결정 필요):** 서명이 없어 SmartScreen 경고와 백신 오진이 생깁니다. 인증서를 사면 빌드에 서명 단계를 넣습니다.
  인증서가 없으면 이 항목은 미룹니다.
- 확인: 켜진 이전 버전 위에 설치, jar가 지워진 설치, 포트가 막힌 경우를 시험 절차로 적고 GitHub Actions 빌드로 확인합니다.

## 2단계: 속도

0단계 결과에 따라 순서를 정합니다. 후보:

- **켜는 시간:** Java 시작 캐시(AppCDS, 설치 파일 빌드에서 만들어 넣음), 시작할 때 꼭 필요하지 않은 일 미루기(글꼴 색인 등).
- **메모리:** `-Xmx3g`를 측정에 맞게 조정.
- **썸네일·미리보기:** PDFBox 그리기가 느리면 PDFium(BSD·Apache 라이선스, 크롬의 PDF 엔진)을 Java 25 FFM으로 불러
  그리기만 맡깁니다. 글자 편집·가리기·내보내기는 지금처럼 PDFBox. 두 엔진의 결과 차이(글꼴·가림 영역 표시)를 테스트로 확인합니다.
- **무거운 픽셀 계산:** 스캔 글자 지우기·글꼴 모양 비교·용량 줄이기가 느리면 먼저 Java 안에서 고치고(병렬화, 불필요한 다시 그리기
  제거), 그래도 느릴 때만 그 부분을 Rust DLL로 떼는 것을 검토합니다. 전체를 Rust로 바꾸지 않습니다.
- 각 개선은 0단계 측정으로 전후를 비교해 이 문서에 적습니다.

## 3단계: 프로그램 창으로 실행

지금은 실행하면 기본 브라우저에 탭으로 열리고 트레이 아이콘으로 끕니다.

- **1차(작게 시작):** Edge의 앱 모드(`msedge --app=http://localhost:<포트>`)로 주소창·탭 없는 창을 엽니다. Windows 10·11에는
  Edge가 있습니다. 창 이름·아이콘, 창을 닫으면 앱도 끌지(또는 트레이에 남길지) 정합니다. Edge가 없거나 실패하면 지금처럼 기본 브라우저.
- **2차(필요하면):** WebView2를 쓰는 작은 실행기(.NET 또는 Rust/Tauri)를 만들어, 실행기가 Java 서버를 띄우고 자기 창에 화면을
  보여 줍니다. 1단계의 "켜지지 못하면 알리기"·"이전 버전 넘겨받기"도 이 실행기가 맡을 수 있습니다. 실행기의 라이선스·서명·백신 문제를 함께 검토.
- 파일 끌어다 놓기, 내려받기(저장 위치 묻기), 인쇄, 오른쪽 클릭, 한글 편집기(iframe)가 창 안에서도 되는지 e2e로 확인합니다.
- 창 크기·위치를 기억하고, 같은 앱을 두 번 실행하면 이미 열린 창을 앞으로 가져옵니다.

## 4단계: 화면 정리

기능이 늘면서 첫 화면 리본(파일·편집·선택한 페이지·검토·보안·내보내기)과 편집 화면 메뉴가 복잡해졌습니다.

- 먼저 지금 화면의 모든 버튼·메뉴·단축키 목록을 만들고(어디에 무엇이 있는지), 겹치는 것과 거의 안 쓰는 것을 표시합니다.
- 원칙: 자주 쓰는 일(열기, 페이지 정리, 글자 고치기, PDF로 내보내기)은 한눈에, 나머지(용량 줄이기, 암호, 사진 내보내기, 문서 비교,
  글자 인식 세부)는 묶어서 한 단계 안에. 같은 일은 어디서나 같은 이름·아이콘. 첫 화면은 "파일을 끌어다 놓으세요" 중심으로 단순하게.
- 내보내기는 하나의 `내보내기…` 창(형식: PDF·사진, 옵션: 이미지로 변환·용량 줄이기·암호)으로 모으는 것을 검토합니다.
- 바꾼 화면은 스크린샷으로 전후를 남기고, 바뀐 위치를 릴리스 노트와 도움말에 적습니다. e2e 테스트의 버튼 이름도 함께 고칩니다.
- 화면 디자인 시안을 먼저 보여 주고 확인받은 뒤 구현합니다.

## 5단계: 이름·버전 정리

- 내부 이름 정리: `pdfedit-v2-backend`(Gradle 프로젝트·jar 이름), README 제목 `pdfedit_v4` 등. 설치 파일·업그레이드 코드·데이터
  폴더 이름은 자동 업데이트 때문에 그대로 둡니다.
- 버전: v5 첫 릴리스의 `app.version`을 정합니다. Windows 버전은 `1.0.<app.version×1000>`이고 낮아지면 업그레이드가 막히므로,
  예를 들어 `5.000`이면 `1.0.5000`으로 0.118(`1.0.118`)보다 큽니다. 계산 방식(`build-installer.ps1`, 업데이트 비교 코드)이
  새 번호에서도 맞는지 테스트로 확인합니다.
- README·docs를 v5 기준으로 고칩니다.

## 진행 방식

- 단계마다: 작업 브랜치에서 개발 → 테스트 → GitHub Actions로 시험 설치 파일(릴리스 없이) → 사용자가 설치해 확인 → master 합치기 →
  릴리스. master 합치기와 릴리스는 사용자가 요청할 때만 합니다.
- 큰 결정(코드 서명 인증서 구입, 창 방식 2차 실행기, 화면 시안)은 사용자에게 먼저 묻습니다.
- 각 단계가 끝나면 이 문서의 해당 단계에 결과(측정치, 바뀐 것, 남은 일)를 적습니다.
